# Groov

A habit-tracking mobile app built with Expo and React Native. Users create daily or volume-based habits, track completion streaks, run personal challenges linked to specific habits, review historical progress, and receive AI-generated coaching and reflections powered by Claude Opus.

## Features

- **Daily & volume habits** — binary (done/not done) or numeric goal per day
- **Streaks** — per-habit and overall, computed live from history; snapshot-aware so deleting a habit doesn't rewrite the past
- **Challenges** — up to 3 active at once; earn platinum / gold / silver / copper tiers on completion
- **Progress view** — bar chart + heatmap with 7 / 30 / 90-day periods
- **AI Coach (Daily Nudge)** — personalized motivational message generated each day by Claude Opus; highlights your strongest habit and gives one actionable tip for the weakest one
- **AI Reflection** — on-demand weekly or monthly summary generated by Claude Opus; identifies patterns, consistency trends, and gives a concrete improvement tip
- **Cloud sync** — Supabase backend with RLS; multi-device; sign in / sign out via email + password
- **Per-habit reminders** — push notifications at a user-chosen time; mirrored in Settings
- **Light / dark theme**
- **Haptic feedback and audio chimes** on completions and UI actions
- **Custom habit icons** — pick from emoji grid or device photo library / camera
- **Onboarding** — 3-slide walkthrough on first launch; `resetAll()` returns to it instantly

## Navigation (`App.js`)

**Custom slide navigator** — no React Navigation. All 5 screens render side-by-side in a `flexDirection: 'row'` `Animated.View` that is `SCREEN_WIDTH × 5` wide. The active screen is shown by translating to `-activeIndex × SCREEN_WIDTH`.

- **Tab tap:** `goToTab(i)` → `Animated.timing` over 180 ms (`Easing.out(Easing.quad)`)
- **Swipe:** `PanResponder` requires `|dx| > 12` and `|dx| > |dy| × 1.8`. Release threshold: `SCREEN_WIDTH × 0.25`
- Off-screen slots use `pointerEvents="none"`
- `isAnimating` ref blocks double-fires during transition
- **Swipe lock:** `modalOpenRef` (synced from `context.modalOpen`) blocks swipe while any bottom sheet is open
- **Cross-screen navigation:** `requestedTab` in context; when set by any screen, `AppNavigator` calls `goToTab()` then clears it

**Tab order:**

| Index | Screen | Ionicons icon |
|---|---|---|
| 0 | TodayScreen | home-outline |
| 1 | ProgressScreen | bar-chart-outline |
| 2 | ChallengeScreen | trophy-outline |
| 3 | HabitsScreen | clipboard-outline |
| 4 | SettingsScreen | settings-outline |

> **Rules of Hooks:** All hooks in `AppNavigator` must be declared **before** the conditional `if (!hasOnboarded) return <OnboardingScreen />`. Breaking this causes "rendered fewer hooks than expected" when `resetAll()` flips `hasOnboarded` to false.

## Data Models

All data persisted as JSON in AsyncStorage.

### Habit
```js
{
  id: string,              // Date.now().toString()
  name: string,
  icon: string | null,     // emoji; null if customIconUri is set
  customIconUri: string | null,
  type: 'daily' | 'volume',
  volumeGoal: number,      // 1 for daily, 2–N for volume
  createdAt: string,       // 'YYYY-MM-DD'
  reminder: {
    enabled: boolean,
    hour12: number,        // 1–12
    minute: number,        // 0–59
    ampm: 'AM' | 'PM',
  } | undefined,
}
```

### Completions
```js
{ 'YYYY-MM-DD': { [habitId]: number } }
```

### Daily Snapshot
Written whenever `habits` changes. Ensures historical totals remain accurate after habits are added or deleted.
```js
{ 'YYYY-MM-DD': [{ id, name, icon, volumeGoal }, ...] }
```

### Challenge (active)
```js
{
  id: string,
  name: string,
  description: string,
  icon: string,              // emoji, default '🏆'
  days: number,              // total duration
  completedDays: string[],   // 'YYYY-MM-DD' — date-based, not index-based
  completed: boolean,
  startDate: string,         // 'YYYY-MM-DD'
  linkedHabitIds: string[],  // habit IDs that count toward this challenge
}
```

- Max **3 challenges** simultaneously
- `currentDay = min(days, daysSince(startDate) + 1)` — calendar-based progression
- When `daysSince(startDate) >= days` the challenge auto-archives on the next ChallengeScreen render

### Past Challenge
```js
{ ...challenge, archivedAt: 'YYYY-MM-DD', tier: 'platinum'|'gold'|'silver'|'copper'|'none' }
```

### Completion Tiers

| Tier | Threshold | Badge | Colors |
|---|---|---|---|
| platinum | 100% | 💎 | `#CCFFFE` / `#22D3EE` |
| gold | ≥ 75% | 🥇 | `#FEF3C7` / `#F59E0B` |
| silver | ≥ 50% | 🥈 | `#F1F5F9` / `#94A3B8` |
| copper | ≥ 25% | 🥉 | `#FDE8D8` / `#CD7F32` |
| none | < 25% | 📋 | theme defaults |

`getChallengeTier(completedCount, totalDays)` and `TIER_STYLES` are named exports from `AppContext.js`.

### Settings
```js
{
  notificationsEnabled: boolean,
  reminders: [{
    id: string,        // 'reminder-{uuid}' general | 'habit-{habitId}' per-habit
    label: string,
    time: { hour12, minute, ampm },
    enabled: boolean,
    habitId?: string,  // present when mirroring a habit reminder
  }],
  soundEnabled: boolean,
  hapticsEnabled: boolean,
  theme: 'light' | 'dark',
}
```

`migrateSettings()` converts legacy `morningTime` / `eveningTime` fields to `reminders[]` on load.

## Screen Behaviours

### TodayScreen

- Purple `SafeAreaView` extends the header colour into the iOS status bar. `ScrollView` uses `theme.bg`.
- **Mark All / Unmark All:** Mark All → `selectAllHabitsToday()` + auto-claims all eligible challenges (`assumeAllDone=true` because state hasn't flushed yet) + `playSuccessChime` + `hapticFillSequence` + `CompletionCelebration`. Unmark All → `resetAllHabitsToday()` + unmarks all challenge days for today.
- **Per-habit increment:** auto-claim computed synchronously using pre-increment `completions` state — avoids the stale-closure bug that occurs with `setTimeout` + `isAllDone()`.
- `allDoneCelebrated` ref resets on any decrement and on date change (`useEffect([today])`) — without the date-change reset the first Mark All on a new simulated day skips the animation.

### ChallengeScreen

Two archive paths that never double-archive:
1. **Immediate** (`completeChallengeImmediately`): called from TodayScreen when the user finishes the final calendar day of a challenge while incrementing a habit. Removes from `challenges` and adds to `pastChallenges` atomically.
2. **Calendar expiry** (`archiveExpiredChallenge`): called from ChallengeScreen's `useEffect([today])`. Since already-completed challenges are already removed, this path never re-archives them.

`HabitLinkModal` always receives `challengeId` + the live `challenges` array — never a snapshot — so link/unlink toggles reflect instantly without reopening the modal.

### HabitsScreen

- **Reminder sync:** saving a reminder adds a mirrored `{ id: 'habit-{id}', habitId, ... }` entry to `settings.reminders`; toggling off updates `enabled: false` in both places; `deleteHabit` removes the entry automatically.
- **Pending link flow:** `pendingHabitLinkChallenge` is set by ChallengeScreen; a 400 ms `useEffect` delay opens the Add Habit modal after the slide animation finishes; `addHabit()` returns the new ID for immediate linking.

### SettingsScreen

Reminders with `habitId` display the linked habit's icon and a read-only "Habit" label. Toggling or changing the time syncs back to `habit.reminder` via `updateHabit`. The trash icon removes the entry and disables `habit.reminder.enabled`.

| Table | Purpose |
|---|---|
| `habits` | Habit definitions |
| `completions` | `(user_id, date, habit_id, count)` — one row per habit per day |
| `challenges` | Active challenges |
| `past_challenges` | Archived challenges with `tier` + `archivedAt` |

| `ai_reflections` | `(user_id, period, period_start, period_end, message)` — one cached reflection per user per period_start date |

### Sync Strategy

- **On login:** pull cloud data if it exists (multi-device); push local AsyncStorage data if cloud is empty (first-time migration).

- **On account delete / reset:** `deleteAllUserData(userId)` deletes from all 8 tables including `ai_nudges` and `ai_reflections`.

## AI Coaching

### Architecture

```
Mobile App
    │  supabase.functions.invoke()   (JWT auto-attached)
    ▼
Supabase Edge Function  (Deno runtime)
    │  reads habits + completions + streaks from DB
    │  calls Claude Opus API
    ▼
Anthropic API  →  message text
    │
    ▼
Edge Function caches result in ai_nudges / ai_reflections
    │
    ▼
Mobile App renders card
```

### Edge Functions

Both functions are deployed to the Supabase project and use `npm:` specifiers for Deno imports.

**`generate-nudge`** (`supabase/functions/generate-nudge/index.ts`)
- Called automatically when TodayScreen mounts (once per app session, guarded by `nudgeFetched` ref).
- Checks `ai_nudges` for a cached entry matching today's UTC date → returns it instantly if found.
- Otherwise: fetches habits + last 30 days of completions, computes per-habit streak and 30-day completion rate, calls `claude-opus-4-8` with a targeted prompt (≤ 250 tokens), then upserts the result.
- Returns `{ message: string, cached: boolean }`.
- If user has no habits, returns `{ message: null, reason: 'no_habits' }` and no card is shown.

**`generate-reflection`** (`supabase/functions/generate-reflection/index.ts`)
- Called on-demand when the user taps "Generate weekly/monthly summary" in ProgressScreen.
- Accepts `{ period: 'weekly' | 'monthly' }` in the request body.
- Cache key: `(user_id, period, period_start)` where `period_start = today − N + 1 days`. A new cache entry is created each day, so the user can generate a fresh reflection daily.
- Fetches habits + completions for the period, computes per-habit `completedDays/N` and `rate%`, counts perfect days, then calls `claude-opus-4-8` (≤ 400 tokens).
- Returns `{ message: string, cached: boolean, generatedAt: string }`.

### UI Integration

**TodayScreen — AI Coach card**
- Appears above the habits list, styled with `theme.primaryLight` background and `theme.primary` border.
- State: `nudgeMessage` (string | null), `nudgeLoading` (bool), `nudgeFetched` ref.
- The card only renders when `nudgeLoading || nudgeMessage` — silent failure if the fetch errors (card never appears).
- `nudgeFetched` ref prevents re-fetching on re-renders; resets on app restart. Guarded by `habits.length === 0` so it won't call the edge function when there are no habits.

**ProgressScreen — AI Reflection card**
- Appears below the heatmap card.
- Period toggle (7d / 30d) resets `reflectionMessage` and requires a new "Generate" tap.
- States: `reflectionPeriod`, `reflectionMessage`, `reflectionLoading`, `reflectionError`, `reflectionGeneratedAt`.
- Shows "Generation failed — please try again." on error with the Generate button still accessible.
- Displays the generation date (`Generated Jun 4`) under the reflection text.

### Client Service (`src/services/aiCoaching.js`)

```js
fetchDailyNudge()           // → { message, cached }
fetchReflection('weekly')   // → { message, cached, generatedAt }
fetchReflection('monthly')  // → { message, cached, generatedAt }
```

Both functions call `supabase.functions.invoke()` (JWT auto-attached from stored session), then read the actual error body from `error.context.json()` on failure for meaningful error messages.

### Caching Behaviour

| Feature | Cache key | Behaviour |
|---|---|---|
| Daily nudge | `(user_id, date)` UTC date | One generation per day; subsequent calls are instant DB reads |
| Reflection | `(user_id, period, period_start)` | One per period_start date; changes daily as the window rolls forward |

### Model

Both features use `claude-opus-4-8`. Max tokens: 250 (nudge), 400 (reflection). No streaming — full response awaited before returning.

## Key Design Decisions & Gotchas

**Auto-claim stale closure:** Never call `isChallengeHabitsDone()` inside a `setTimeout` in `handleIncrement` — the `useCallback` closure captures stale state. Instead, compute inline immediately after `justCompleted === true`, treating the just-completed habit as done and reading `completions[todayStr()]` directly for all others.

**completeChallengeImmediately vs archiveExpiredChallenge:** The two paths compose safely because `completeChallengeImmediately` removes the challenge from `challenges` atomically — ChallengeScreen's expiry `useEffect` will never find it again.

**`allDoneCelebrated` must reset on date change:** Without `useEffect([today])` resetting the ref, the first Mark All on a new simulated day (dev date offset) silently skips the completion animation.

**HabitLinkModal live data:** Pass `challengeId` + live `challenges` array, not a snapshot. The modal re-derives its challenge object on every render so link/unlink is instant.

**Challenge days are date-string-based:** `completedDays` stores `'YYYY-MM-DD'` strings. Day badges compute `startDate + i days` and check `includes(that date)` — correct even when days are skipped.

**7d heatmap always one row:** Uses `flex: 1` + `aspectRatio: 1` per cell in a non-wrapping row. `HEAT_INNER = SCREEN_WIDTH - 90` (scroll padding 48 + card padding 40 + border 2) — update if card padding changes.

**Bottom sheet swipe lock:** Every screen that opens a sheet calls `setModalOpen(true/false)`. `AppNavigator` checks `modalOpenRef` in `onMoveShouldSetPanResponder`. Without this, swiping an overlay navigates screens.

**Sound cache invalidation:** `FileSystem.getInfoAsync(uri)` is called before reusing a cached WAV path because iOS can clear `cacheDirectory` at any time.

**`resetAll()` is synchronous:** All React state resets in one call — app returns to onboarding with no restart.

**AI nudge fetches only once per app session:** `nudgeFetched` is a `useRef` (not state), so it survives re-renders but resets on app restart. This prevents duplicate Anthropic API calls on every render while still refetching after a full reload.

**`supabase.functions.invoke` error body requires `error.context.json()`:** The Supabase JS client sets `data = null` and returns a `FunctionsHttpError` when a function responds non-2xx. The actual JSON error body from the function (e.g. `{ error: "Invalid API key" }`) is on `error.context` as an unconsumed `Response` object — call `.json()` on it to read it.

**AsyncStorage over SecureStore for Supabase auth:** The Supabase JS client's default `SecureStore` has a 2 KB value limit which the session JWT can exceed, causing silent auth failures. `AsyncStorage` has no such limit.

## Known Limitations

- Notification delivery in Expo Go varies by device; not verified on all Android configurations.
- Custom habit icon URIs are local device paths — they do not persist across app reinstalls.
- If a habit is renamed, its mirrored label in Settings > Notifications shows the original name. Deleting and re-adding the reminder refreshes it.
- `pendingHabitLinkChallenge` uses a 400 ms delay before opening the Add Habit modal to let the tab slide animation finish.
